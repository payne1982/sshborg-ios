<en-US>
• Mosh (experimental): a terminal that survives a change of network and the phone being put away. The screen lives on the server, so the same shell with the same programs still running in it is there when you come back. Turn it on per host — the server needs mosh-server installed and its UDP ports reachable.
• Mosh through a bastion: a host whose first hop has Mosh on is reached the other way round — Mosh to that machine, then one ssh line from there — so the terminal sits where the network does not change.
• The file editor no longer cuts a file short when a save is interrupted: the new version is written aside first, and the original stays on the server until it has been replaced. It also keeps the file's permissions exactly.
• SFTP: file names sent by a server are checked before they are used, so a server cannot point the app outside the folder you are looking at.
• Jump hosts: choosing them now starts from your own host list, with the typed form a tap away.
• App lock with your own PIN or passphrase: a lock that needs neither Face ID nor the device passcode. Five wrong tries lock it for a while, longer each time — and a forgotten one cannot be recovered, so the app says so before you set it.
• Security: when you approve a server's key, only that exact key is accepted from then on — for every machine in a jump-host chain, and for port forwarding too. A mosh-server command restored from a backup can no longer run anything but the program it names.

• Mosh（实验性）：终端可以经受网络切换和手机放进口袋。屏幕保存在服务器上，所以回来时还是同一个 shell，里面的程序仍在运行。按主机单独开启——服务器上需要装有 mosh-server，并且它的 UDP 端口可以连通。
• 通过堡垒机使用 Mosh：如果某台主机的第一跳开启了 Mosh，就反过来连接——先用 Mosh 连到那台机器，再从那里执行一行 ssh——这样终端就待在网络不会变化的地方。
• 保存中断时，文件编辑器不再把文件截断：新版本先写在旁边，原文件在被替换之前一直留在服务器上。文件的权限也会原样保留。
• SFTP：服务器发来的文件名在使用前会先检查，这样服务器无法把应用指向你正在查看的目录之外。
• 跳板主机：现在从你自己的主机列表开始选择，手工输入的方式仍然只差一次点按。
• 用你自己的 PIN 码或口令锁定应用：既不需要面容 ID，也不需要设备密码。连续输错五次会锁定一段时间，每次更久——忘记的口令无法找回，所以应用会在你设置之前说明这一点。
• 安全：你确认某台服务器的密钥后，之后只接受这把确切的密钥——跳板链中的每台机器如此，端口转发也是如此。从备份恢复的 mosh-server 命令不能再执行它所指定程序以外的任何东西。
